# 2.0.0 整体整理与维护边界

本轮覆盖整个订阅插件的组装、设置和前端模块边界；不以改写每个已有模块作为重构完成的标准。登录状态机、凭据保险库、网络传输、限额重置和原图存储已有独立职责，保留其实现并运行原有行为回归。

## 模块职责

| 层 | 入口/模块 | 职责 |
| --- | --- | --- |
| 主机组装 | index.js | 创建账号、模型、搜索、图片和额度服务，绑定 DSH 生命周期 |
| 主机 RPC | subscription-rpc.js | 路由、参数校验、错误脱敏、账号变化后的缓存失效 |
| 通信契约 | rpc-contract.js | 通道名称与客户端响应解析，避免各控制器重复定义 |
| 通信适配 | subscription-transport.js | 将订阅端点注册为 DSH `/api` 精确 Fetch 路由；沿用 DSH 认证、请求体上限及 RPC envelope schema，保留关联 ID 与取消信号 |
| 配置契约 | settings-contract.js、preference-fields.js、capability-settings.js、image-features.js | 旧设置迁移、枚举、默认值、功能开关；Host 枚举 schema 与 RPC 写入共用数据 |
| 客户端组装 | client.jsx | 安装样式、设置页、输入框扩展、查看器和生命周期清理 |
| 客户端业务 | client-account、client-preferences、client-model-select、client-quota、client-composer-quota、client-usage、client-diagnostics、client-section | 各业务界面独立维护，使用已有 controller；不再在一个千行入口中交错编辑 |
| 图片服务 | codex-images.js、image-models.js、image-original-* | 模型/质量解析、权限检查、请求和结果处理、原图完整性 |
| 图片输入 | image-composer.js、sketch-trigger.js | 统一附件接收/失败释放、草稿保护、正式 @ 触发来源 |
| 图片工作台 | sketch-document.js、sketch-workspace.jsx、sketch-styles.js、image-library.jsx、image-gallery.js | 笔画与导出、画板交互、样式、会话目录、多选与比较 |

## 保持的行为

- OAuth 留在 DSH 主机，不读取 Codex CLI 登录，不加入 API key 后备。
- 登录、退出、切换账号后的用量和模型缓存生命周期继续由既有主机服务控制。
- 用量重置仍需已有明确确认流程；画板、图库和测试不会消费重置卡。
- 普通对话模型和图片模型独立；Luna 是测试对话模型，不是图片工具专用限制。
- 历史工具结果、原图校验、引用归属、PNG 路线及旧设置继续兼容。
- 图片的生成和编辑独立开关，执行前和网络请求前再次检查。关闭不删除历史产物。

## 新交互的边界

- @Sketch 注册到 DSH inputTriggers；消费有版本校验的 token span，不监听全局键盘。不具备此可选服务时仍有草图按钮。
- 草图导出 PNG 附件，不自动发送；绘画与本地对比不调用模型。画布限制 200 笔、每笔 2000 点，避免无限增长。
- `@Image` / `@生图` 与自然语言调用并存，共用草稿接收和设置，没有另建直接付费发送通道。快捷入口可独立关闭；候选选择消费经过版本校验的 span，只打开面板，确认后只追加用户可见的简短创作请求。
- 同时关闭生成和编辑时，`image-tool-registration.js` 撤销工具注册；后续工具目录不再包含图片 schema。再次启用只注册一次。关闭期间既有工具执行仍由网络请求前的开关检查阻止；已发送给服务端的生成任务不能承诺撤回。保留历史结果，避免破坏对话回放。
- 界面状态不额外写入会话。发送后的提示、参考图及生成图仍是上下文的一部分；快捷入口不等于清空历史，也不承诺消除图片用量。工具说明压缩重复措辞，保留用户意图、引用归属及编号评论等规则。
- 模板提供海报、商品图和图标的不同提示骨架，用户的详细要求写入可编辑草稿。
- 图片库只读取当前会话最近 100 张订阅生成图，按附件去重；缩略图进入可视范围才加载。多选最多 5 张，按选择顺序附加原图；不是批量发起多个生成请求。
- 并排对比由用户选择两张，不推断唯一父图，也不声称不同分辨率像素对齐。
- 图上自由涂画原图、真实 mask、部分帧流式返回、非 PNG 输出尚未实现；编号评论与草图不能冒充 mask。
- 2.5 候选型号标为实验；Flare 已接受一次订阅请求并返回图，服务端未报告型号。不能推广为所有账号支持，也不能由此证明 Sunburst 的可用性。

## 维护要求

新增配置先落契约，再接 Host 执行和客户端；不能只藏按钮。组件不直接访问凭据。添加图片输入统一走 image-composer 的接收与失败清理。测试以可观察行为为主，源码交付检查跟随模块移动更新，但不删除原有安全断言。构建产物随源码更新，实际安装包验收后再决定发布。

新增功能没有引入运行时依赖。新增画板/图库会增加客户端产物体积，不能把源码拆分宣称为包体缩小；体积数据随最终验收记录报告。

0.1.5-alpha.1 的 Connection 已将 webServer 改为内部可选注入，但自定义 `rpc.handle` 仍从服务原始上下文读取 webServer，实机抛出 `cannot get property "webServer" without inject`。客户端因此收到路由缺失的 405。2.0 统一改用官方 `connection.fetch.register`，不修改 DSH 源码或全局配置，不占用 Remote 独占的 `/api` interceptor。18 个端点都进入官方认证桥；未登录 401、外部 Origin 403 已在稳定版和 alpha 实测。

2.0 的正式兼容基线收敛为 DSH 0.1.2-rc.1，0.1.5-alpha.1 保持预览通道。检查 npm 上的旧 Connection 包发现早期版本没有精确 Fetch 注册接口，因此不继续复制 1.x 的旧版本兼容声明。使用更早 DSH 的用户应先升级宿主，或保留 1.x；本轮没有自动升级用户宿主。预览通道通过设置/通信验收不代表全部模型和图像任务均已在该通道实测。
