# 支持诊断审计

现有服务端报告覆盖登录状态、网络请求分类、模型目录、设置可写性，以及 WebSocket / 压缩计数。它不能证明客户端功能已显示，也不能证明没有插件冲突。

本次增加按需生成的客户端报告：

| 检查 | 能确认的事实 | 限制 |
| --- | --- | --- |
| 额度数据链路 | 设置未就绪、关闭、其他模型提供方、未登录、加载中、请求失败、无匹配额度、数据就绪 | 不把其他模型额度当作当前模型额度 |
| 额度显示 | 元素不存在、样式隐藏、零尺寸、视口外、中心被覆盖、中心可见 | 中心命中测试不代表每个像素正常；设置弹窗也会遮挡 |
| 宿主插槽 | 额度和模型选择器注册、宿主选中或被替换 | 不支持选举查询的宿主明确标为未知；不猜测责任插件 |
| 样式与版本 | 样式是否存在、客户端与服务端版本是否一致 | 同版本号的开发构建差异不在此检查范围 |
| 可读结论 | 请求失败、设置不可写、插槽替换等具体证据 | 没有发现不等于所有功能通过验收 |

检查仅针对当前挂载的输入框。没有挂载时不报告“正常”或“冲突”。报告不读取其他插件配置、DOM 文本、账号标识、对话、页面 URL 或登录凭据；不自动上传，不发模型请求，不消耗重置卡。检查使用当前状态，网络历史记录可能早于问题发生。

尚未覆盖：具体 CSS 规则责任来源、其他插件的运行行为、未执行过的搜索/生图/子任务功能正确性、每个草图操作的结果。这些仍需针对性复现，不能由一份快照保证。

验收包含状态分类、祖先隐藏、遮挡、零尺寸、卸载清理、旧宿主缺少接口、插槽替换和隐私字段测试；另在官方 DSH 0.1.7-rc.1 中检查真实设置页报告。诊断生成和复制失败分开提示，复制失败仍可展开手动复制。
