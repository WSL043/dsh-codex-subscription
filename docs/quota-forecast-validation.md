# 续航估算的验证与转正方案

当前估计回答“继续保持最近速度，额度大约还能持续多久”，不能预知后续任务难度、模型切换或用户停止使用。详情的范围是速度离散度与额度报告精度形成的估计范围，不是统计置信区间。

## 本轮落地

- 最多使用最近两小时的样本，避免全天空闲稀释当前消耗。
- 同一缓存响应按 fetchedAt 记录，不把多次读取误作新观测；过期响应不进入估算。
- 超过 90 分钟的观测断档、额度增长或重置开启新一轮校准。
- 保留原始读数，不擅自假定小数精度；按未知取整误差建立速度区间。区间仍包含零时，只有至少 5 分钟、3 个新鲜样本和 1 个百分点的实际下降才提供近期平均初步估计。平稳不变或单次跳格不生成精确倒计时。
- 保留账号、额度池、周期隔离。缺失重置时间不能解释成“足够用到重置”。
- 详情展示估计范围；短摘要仍为近似值。只有保守范围也能覆盖重置时间才提示够用到重置。

## 下一步验收

使用用户已主动开启预测后保存在本机的历史，不新增后台上传。历史不足时继续采集，不能用合成样本代替真实准确率。

逐点回放必须只使用该时刻之前的样本。按账号和额度池分别统计，训练与评估按日期切分，避免未来数据泄漏。分别覆盖持续编码、短时突增、切换模型、长时间空闲、额度量化、重置和请求失败。

记录未来 15／30／60 分钟消耗的绝对百分点误差和 P90 误差，同时记录区间覆盖率、暂停估算比例与“足够到重置”的错误肯定。未发生耗尽的周期不能当作真实耗尽时间来计算时长误差。

与旧版全天中位斜率、最近一小时端点速度两条基线比较；如果改善只来自更频繁地拒绝预测，也不能直接判定升级成功。明确呈现误差与可用率的权衡。预先制定用户可接受的阈值，积累多个完整周期并在不同使用模式上验证后，才考虑移除 Beta。
