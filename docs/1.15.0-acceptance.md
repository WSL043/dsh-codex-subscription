# 1.15.0 能力审计与验收

状态：候选版本，未发布。上线前必须完成下面的订阅账户实机验收；隔离安装和合成响应测试不能替代真实服务端结果。

## 本版变化

- 模型目录同时保留默认窗口和显式最大窗口。新型号自动出现于上下文设置；已有逐模型设置继续读取，新覆盖值独立保存。DSH 的模型缓存也随覆盖值变化失效。
- Fast 的界面与请求使用同一份模型能力元数据。Astra 的提示更新为约 2 倍速度，其他型号不再一律宣称 1.5 倍。没有在线元数据时使用内置已知型号能力。
- 手动刷新模型，并显示内置/账户在线目录和加载状态；失败保留已有目录和草稿。
- 订阅搜索增加实时、缓存（实验）和停用。默认仍为实时。停用在授权读取和搜索请求前阻止调用；缓存传递 `external_web_access: false`，账户端行为尚待验收，不能把这个字段测试称为缓存搜索实证。
- 最多 20 个搜索结果域名筛选，匹配域名及其子域名，拒绝协议、路径和通配符。它不是网络访问白名单，也不保证服务端只搜索指定站点。
- 可关闭额度提示、剩余不超过 20% 时提示，或对不超过六小时的窗口提前到 50%。排除已重置、超过五分钟和代码审查额度；失败不假报零额度。账户切换清除旧额度。
- 原图下载显示进度，可取消后续分块；保留会话授权、尺寸边界、逐块一致性和完整 SHA-256 校验。已发出的单块 RPC 可能仍完成，取消后不会保存图片。
- 本机设置对象经主机复制后不会误报保存失败；主机拒绝但没有抛异常时仍可重试原设置。

## 能力边界

| 能力 | 插件实现和维护责任 | 证据与剩余验收 |
| --- | --- | --- |
| OAuth、设备登录、续期、多账号 | 使用 DSH 凭据服务，手动选账号，过期重登与旧响应隔离 | 现有登录、凭据、账户和网络行为测试；需用户真实登录/续期验收 |
| 模型、推理等级、图片输入 | 账户目录发现，原生 pi-ai / DSH 适配；仅暴露双方支持的字段 | 模型目录及传输契约测试；实际型号权限以账户为准 |
| Fast、输出详细度、上下文 | 订阅请求字段和动态模型能力；标准模式保留目录默认 | 本版迁移/新模型测试；真实请求需账户确认 |
| 工具调用、流式输出、推理重放、提示缓存 | 保留官方适配器语义，使用 SSE 避免跨账号复用旧 WebSocket 连接 | 传输和会话契约测试；不把本机设置视为服务端缓存命中证据 |
| 多窗口额度、Credits、预测 | 显示服务端实际返回内容，预测为本地估算 | 额度、预测持久化和竞态测试；实机比较服务端额度 |
| 重置卡 | 检查、冷静期、知情确认、幂等与不确定状态保护 | 失败注入及幂等测试；不得为验收自动消耗卡片 |
| 订阅搜索 | 当前模型路由、结构化来源、明确错误、不回退付费 API | 请求及过滤测试；实时/缓存均需账户端确认 |
| 生图、编辑、原图 | 保留订阅图片工具，参考图选择、质量/尺寸/背景及标注工作流 | 图像请求、附件、原图和编辑契约测试；需真实生图/编辑与原图验收 |
| MCP、技能、浏览器、终端、任务调度 | DSH 的工具和运行时能力，插件提供模型接入 | 不复制整个 Codex 应用，也不制造空开关 |
| Ultra、语音、Codex 云端任务 | Ultra 属于官方客户端编排，并非新增 reasoning 枚举；其他能力需要宿主接口和订阅服务契约 | 当前不作为插件已支持能力，不通过公共 API 文档推断订阅权限 |
| 安装、升级、卸载、诊断 | 官版 DSH bundle 生命周期，隐私受限诊断，人工发布 | 稳定版及 alpha 版分别安装验证；本版不触发发布 |

## 账户实机清单

在隔离的官版 DSH 中自行登录，不需要给维护者提供 token。先保持标准速度、标准上下文和实时搜索，之后逐项改变一个设置。

1. 登录后刷新模型；检查账户实际可用型号、推理等级和 Fast。切换账号时，目录和额度不能残留前一账户的数据。
2. 用可用模型完成普通对话、一次工具调用和一次带图提问。分别切换 Fast 与输出详细度，记录是否成功及实际错误；速度倍数不作为单次请求的必达标准。
3. 保存某模型自定义窗口，刷新页面、重启 DSH，检查仍生效，再恢复标准。只做实际需要的长会话，不为验收浪费额度。
4. 分别做实时和缓存搜索，检查链接、引用、服务端错误。停用后必须明确失败。设置域名后检查每条结果符合域名范围；若缓存不支持，保持实验标记并回到实时，不能宣称已补齐官方缓存搜索。
5. 对照账户额度显示及重置时间；低额度提示可在自然使用达到阈值时观察。不要为了测试主动耗尽额度或消耗重置卡。
6. 生图一次，再对同一图标注编辑一次。检查参考图没有丢失、结果可预览，下载原图可打开。下载中取消后应不保存文件，重试应成功。
7. 断网后刷新目录/额度，再恢复网络重试；保留固定错误信息即可，诊断不得含凭据。

记录 DSH 版本、模型、操作、实际结果与时间。未通过项修复并复验后再决定发布；本清单不是发布授权。

## 后续维护方案

优先维持“目录驱动能力 + 官方适配器 + 订阅专属测试”的结构。每次上游变化先对比目录、宿主接口和实际依赖，再决定是否改版。新能力应具备可核对契约、合理用户入口和至少一条真实成功/失败路径，才移除实验标记。indexed 搜索、WebSocket 复用优化、云端任务等分别立项，避免将不兼容的协议或客户端功能塞进模型适配器。

性能工作以可重复的耗时和内存测量为前提。本版延续此前消除图片复制的实现，不引入跨账号缓存，不删除授权和完整性验证来压缩代码。后续可独立拆分设置页与额度展示，但需要可读性或体积收益，不能只以文件变短为目标。
